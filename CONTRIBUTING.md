
# Contributing to biga

Thanks for your interest in contributing to biga.

## Before you start

- Read the README of the repository you intend to change.
- Search existing issues and pull requests before opening a new one.
- For substantial changes, open an issue first to discuss the approach.

## Development

Each repository has its own setup instructions and development workflow. Follow its README rather than assuming all repositories use the same tooling.

## Pull requests

A good pull request should:

- Solve one clearly defined problem.
- Explain why the change is needed.
- Include tests for behavior that could regress.
- Update documentation when behavior or configuration changes.
- Avoid unrelated formatting changes.

Before submitting, run the checks documented by the repository.

## Reporting bugs

Include the affected repository, operating system where relevant, reproduction steps, expected behavior and actual behavior.

Remove access tokens, credentials, private source code and other sensitive data from logs and screenshots.

## Security issues

Do not disclose exploitable vulnerabilities in public issues. Follow [SECURITY.md](SECURITY.md).
